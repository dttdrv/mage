Scope: DOOM 2016 on wine-mage-11.13 (CrossOver 26.2-derived Wine 11.13 + msync,

## 1. Crashes (TOP PRIORITY, unsolved)

### 1a. Exclusive-fullscreen alt-tab crash — ROOT-CAUSED, fix building
- User report: game crashes when Cmd-Tab-ing in **Fullscreen** mode. Repeated.
- Two crashes captured (23:57:02 and 00:11:40): byte-identical callstacks —
  game C++ exception (0xE06D7363) via kernelbase RaiseException, all frames in
  DOOMx64vk.exe. Deterministic.
- Root cause (agent analysis, verified against WindowServer state): exclusive
  fullscreen = CGDisplayCapture + real CGDisplaySetDisplayMode. Cmd-Tab out →
  engine's focus-loss ChangeDisplaySettings(NULL) → winemac restores the
  desktop mode **while inactive** → async reconfiguration #1. Cmd-Tab back →
  engine re-applies CDS_FULLSCREEN → second mode switch possibly while #1 is
  in flight; win32u re-layout positions the game window with stale screen
  geometry (observed Y=-218 == 982-1200 EXACTLY, layer 26). Engine recreates
  its Vulkan swapchain against the inconsistent surface → throws.
  Amplifier: NSApplicationDidChangeScreenParametersNotification storms
  (spurious DISPLAYS_CHANGED bursts during space switches).
- **Fixes:**
  1. SHIPPED (seatbelt, prefix registry): `HKCU\Software\Wine\X11 Driver
     EmulateModeset=y` — win32u satisfies mode changes virtually, no
     CGDisplaySetDisplayMode at all → fullscreen requests behave like
     borderless from next launch; alt-tab becomes a pure window event.
     Universal (driver-agnostic, per-app overridable). Caveat: sub-native
     fullscreen modes letterbox top-left; native res indistinguishable.
  2. BUILT+INSTALLED (real fix, runtime verification pending): winemac patch —
     cherry-pick Wine 11.14 3dcb1a565ae9 (reconfiguration callback replaces
     the notification storm) + defer mode-restores while inactive to
     applicationDidBecomeActive (kills the double-switch; quit-while-inactive
     covered by WindowServer auto-restore on exit). Verify with the
     fullscreen alt-tab torture leg (Block 0, NEXT-SESSION-QUEUE.md) run with
     EmulateModeset REMOVED (seatbelt would mask the winemac fix itself).
- Play in Borderless until fix 2 is verified.

## 2. Black windows

### 2a. Steam UI window permanently black — root-caused, patch building
winemac never requests a redraw on re-exposure: WindowServer purges occluded
layer contents; `windowDidChangeOcclusionState:` (cocoa_window.m:3000) only
does display-link bookkeeping; nothing marks the view dirty again. Fix:
force one redraw from the retained colorImage on re-exposure + deminiaturize
(patch agent running; universal, helps every GDI-surface app).
Interim fix on demand: restart CEF helper (game unaffected).

### 2b. DOOM black-with-HUD-alive (2026-07-21 09:00) — hypotheses
Presents flowing (HUD alive) into a dead-end layer. MoltenVK 1x1-drawable bug
(2A) ruled out: fix 4d74f17e is in v1.4.2-rc1, deployed dylib is 1.4.2.
Leading: MoltenVK never returns VK_ERROR_OUT_OF_DATE_KHR (only SUBOPTIMAL)
and id Tech only recreates the swapchain on OUT_OF_DATE → stale layer after
geometry events (MVKSwapchain.mm:122-138; MoltenVK #1455). Candidate:
env-guarded OUT_OF_DATE escalation patch in our MoltenVK builds.

## 5. Performance — honest state

Frame budget at ~89 FPS (Foundry, 2560x1600 borderless, unlocked):
CPU ~13.5 ms vs GPU ~10 ms — **CPU-bound; ~90% of CPU frame is
Rosetta-translated game code** (translation is the ceiling, GPU has
headroom). Verified shipped levers:

| Lever | Effect | Status |
|---|---|---|
| ROSETTA_ADVERTISE_AVX=1 | +1.9% (isolated A/B) | shipped, default in launcher |
| ntdll inline-recv fast path | kills 2 wineserver roundtrips per ready overlapped WSARecv (DOOM's own threads measured in this path; 11-33k recv/s) | shipped, probe-verified; est. 1-3% via 1% lows — **below perceptibility, as user noted** |
| WINE_CPU_TOPOLOGY port | universal CPU-count cap | shipped default-off; **A/B done 07-22: ~100 vs ~105 — rejected, stays off** (BLOCK3-RESULTS.md) |
| Shader-prefill env | −32%; re-confirmed 07-22: touches 119 → engine locks 60.00 | rejected |
| Async queue submits env | ~88 vs ~103 avg (−15%) | rejected (BLOCK2-RESULTS.md) |
| QoS priority mapping | −2.1% (noise) | rejected |
| Query early-availability MoltenVK patch | every patched leg reached 119–122 for one sample, then pinned at exactly 60.00; later audit found cross-queue, reuse, lifetime and partial-result bugs | **PARKED — unsafe and net −40%; pacing source unresolved** (BLOCK1BC-RESULTS.md) |
| Three-image IMMEDIATE-compatible swapchain | universal arm64/x86_64 hidden-surface tests pass, including dynamic mode switches and recreation | local candidate; in-game A/B waits for the current session to end |

**Cross-block finding (07-22):** the 60-lock is not query-patch-specific.
Both query and prefill legs touched ~120 FPS and then held 60.00 with GPU
time around 6 ms. GPU saturation is ruled out. Engine timing and blocking
on MoltenVK's two-drawable pool were not separated, so attribution remains
open.

**Cull-distance correction (07-22):** the installed experimental x86_64 build
advertises `shaderCullDistance` only to pass DOOM's device check. It does not
implement Vulkan primitive culling and is not a shipping Mage fix. The clean
Mage MoltenVK branch leaves the feature disabled until pre-raster emulation is
implemented and passes CTS.

Ceiling honesty stands: Vulkan-path category capped at ~+12% in the prior
model. CPU-side Rosetta translation remains the largest known vein, while
the 120-touch→60-lock must be diagnosed before further A/B results are used.
